# Tool and MCP Gateway Research

Access date: 2026-05-01

## 1) Research Question
How should FactoryMind AgentOS expose tools and MCP servers to agents safely, while keeping self-learning limited to memory and skills?

The FactoryMind AgentOS must let agents use tools, but learned skills/memory must never expand tool permissions automatically.

## 2) Short Answer
FactoryMind AgentOS should include its own Tool/MCP Gateway.

Recommended v1:

```text
Agent Runtime
  -> ToolRequest
  -> PolicyGate
  -> MCPGateway
  -> Registered MCP Server
  -> Sanitized ToolResult
  -> AuditLog
```

Do not let the LLM connect directly to arbitrary MCP servers.
Do not expose all MCP tools automatically.
Do not trust tool descriptions, resources, prompts, or outputs as instructions.

## 3) MCP Concepts
MCP servers can expose:

| MCP Capability | Meaning | FactoryMind AgentOS Handling |
|---|---|---|
| Tools | Callable actions/functions | Must be registered, scoped, validated, audited |
| Resources | Data/context exposed by URI | Treat as untrusted data; filter and classify |
| Prompts | Prompt templates exposed by server | Do not auto-trust; review before use |
| Roots | Filesystem/workspace boundaries | Restrict and audit |
| Sampling | Server requests model completions | Disable in v1 unless explicitly approved |

V1 FactoryMind AgentOS should support:
- tools
- read-only resources where needed

V1 should avoid:
- remote prompt injection through MCP prompts
- broad roots/filesystem access
- MCP sampling
- unreviewed third-party MCP servers

## 4) Tool Manifest
Every tool must be registered in FactoryMind AgentOS before use.

```json
{
  "tool_id": "project_db.search_projects",
  "server_id": "project_db_mcp",
  "name": "search_projects",
  "description": "Search project records using approved filters.",
  "input_schema": {},
  "output_schema": {},
  "access": {
    "mode": "read|write|admin",
    "scopes": ["project:read"],
    "allowed_agents": ["project_selector"],
    "requires_approval": false
  },
  "limits": {
    "timeout_ms": 5000,
    "max_result_bytes": 50000,
    "max_calls_per_session": 10,
    "rate_limit_per_minute": 60
  },
  "data_policy": {
    "input_privacy": "internal",
    "output_privacy": "internal",
    "allow_model_context": true,
    "redaction_required": true
  },
  "status": "active|disabled|quarantined",
  "version": "1.0.0"
}
```

Tool metadata shown to the model should be generated by FactoryMind AgentOS from the manifest, not blindly copied from the MCP server.

## 5) Permission Model
Tool permission should be scoped by:
- agent
- user
- tenant/company
- tool
- action type
- data class
- session risk

Default v1:
- read-only tools first
- no write tools without approval
- no admin tools
- no filesystem tools
- no shell tools
- no unregistered MCP servers

Self-learning rule:
- skills may suggest when to use allowed tools
- skills may not add or expand tool permissions

## 6) Gateway Flow
```text
1. Agent requests tool by logical tool id.
2. Gateway validates agent is allowed to use tool.
3. Gateway validates input schema.
4. Gateway classifies input data.
5. PolicyGate checks risk and approval requirement.
6. Gateway calls MCP server with scoped identity.
7. Gateway validates output schema and size.
8. Gateway sanitizes output as untrusted data.
9. Gateway writes audit event.
10. Runtime receives sanitized result.
```

Important:
- Model should never receive raw MCP output if redaction/sanitization is required.
- Tool output must be labeled as data, not instructions.

## 7) Tool Output Sanitization
Sanitization should handle:
- prompt-injection phrases
- hidden Unicode/invisible text
- markdown links with suspicious URLs
- secrets/API keys/tokens
- excessive result size
- unexpected schema fields
- executable code snippets where not expected
- instructions telling the agent to ignore rules

Output wrapper:

```json
{
  "tool_id": "project_db.search_projects",
  "status": "success|error",
  "trusted": false,
  "content_type": "data",
  "sanitized": true,
  "data": {},
  "warnings": []
}
```

## 8) Error Taxonomy
Tool errors should map to FactoryMind AgentOS typed errors.

| Gateway Error | Agent Output |
|---|---|
| timeout | `error_retryable` |
| rate limit | `error_retryable` |
| MCP server unavailable | `error_retryable` |
| schema validation failure | `error_tool` |
| permission denied | `error_policy` |
| approval required | `question` or approval request |
| suspected prompt injection | `error_policy` or sanitized continuation |
| result too large | `error_tool` with suggestion to narrow query |
| unknown tool | `error_policy` |

## 9) MCP Security Risks
Research shows MCP introduces several important attack classes:

| Risk | Description | Control |
|---|---|---|
| Tool poisoning | Malicious instructions hidden in tool descriptions | Use FactoryMind AgentOS-owned manifest descriptions |
| Resource poisoning | Malicious data returned as resource/context | Treat all resources as untrusted data |
| Prompt poisoning | MCP prompts contain hidden instructions | Do not auto-use MCP prompts |
| Rug pull | Tool behavior/description changes after approval | Pin server/tool versions and re-validate |
| Shadowing | One tool contaminates context used by another | Isolate tool outputs and label trust boundaries |
| Toxic flows | Safe tools combine into unsafe workflow | Policy checks across tool sequences |
| Data exfiltration | Tool output or prompt causes secrets leak | Redaction, scoped identities, egress controls |
| Hidden Unicode | Invisible injected instructions | Unicode normalization and scanning |
| Overbroad scopes | Agent can access too much data | Least privilege, per-agent scopes |
| Supply-chain risk | Unmaintained/malicious MCP servers | Approved registry and server scanning |

## 10) Existing Systems and References
### MCP Official Specification
What it provides:
- protocol for tools/resources/prompts
- schemas and client-server interaction model
- evolving authorization support

Gap:
- FactoryMind AgentOS still needs application-level authorization, consent, auditing, and policy.

### mcp-agent
What it provides:
- MCP-native agent patterns
- client/server lifecycle support
- durable agents with Temporal

Fit:
- useful reference or possible adapter

Gap:
- FactoryMind AgentOS still needs learning modes, skill governance, and promotion controls.

### Cloudflare Agents MCP Client
What it provides:
- persistent MCP connections in agent storage
- raw MCP tool inspection

Fit:
- useful reference for hosted agent runtime patterns

Gap:
- automatic availability of all tools is not acceptable for our security model.

### OWASP Secure MCP Server Guidance
What it provides:
- secure development practices for MCP servers
- authentication, authorization, validation, isolation guidance

Fit:
- should inform FactoryMind AgentOS secure MCP defaults.

### Invariant MCP Security Research
What it provides:
- tool poisoning and toxic-flow attack research
- MCP scanning concepts

Fit:
- should influence gateway validation and server approval workflow.

## 11) Recommended V1 Gateway Architecture
```text
tools/
  registry.py          # approved tools and manifests
  gateway.py           # call path and policy integration
  mcp_client.py        # MCP client wrapper
  sanitizer.py         # output sanitization
  errors.py            # error mapping
  audit.py             # tool audit events
  schemas.py           # tool manifest and call contracts
```

V1 should support:
- registered MCP servers only
- read-only tools
- per-agent allowlists
- schema validation
- timeouts and result limits
- audit logs
- sanitizer
- policy approval hooks

V1 should not support:
- arbitrary user-added MCP servers
- automatic tool discovery exposed to model
- write/admin tools without approval
- MCP prompts as trusted prompt material
- filesystem/shell tools by default

## 12) Tool Call Audit Schema
```json
{
  "event_type": "tool_call",
  "tool_call_id": "uuid",
  "session_id": "uuid",
  "agent_id": "project_selector",
  "tool_id": "project_db.search_projects",
  "user_id": "string",
  "input_hash": "sha256",
  "output_hash": "sha256",
  "decision": "allowed|denied|approval_required",
  "risk_level": "low|medium|high|critical",
  "duration_ms": 123,
  "status": "success|error",
  "error_type": "timeout|permission|schema|server|policy|null",
  "created_at": "RFC3339"
}
```

Do not store raw sensitive inputs/outputs in audit events unless policy allows it.

## 13) Build-vs-Wrap Decision
Build:
- tool registry
- tool manifest schema
- policy gate
- sanitizer
- audit schema
- permission model
- error taxonomy
- result wrapper

Wrap:
- MCP SDK/client libraries
- mcp-agent patterns if useful
- security scanners where mature

Do not outsource:
- authorization decision
- tool approval
- final sanitization decision
- audit records
- mapping between skills and allowed tools

## 14) Final Recommendation
For FactoryMind AgentOS v1:
- implement our own MCP Gateway
- use official MCP client libraries underneath
- expose only registered tools to agents
- keep tools read-only first
- treat all MCP data as untrusted
- prevent learned skills from expanding tool access
- audit every tool call

This is required for industrial use because MCP tools become the agent's real-world action surface.
